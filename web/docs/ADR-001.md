# ADR-001: Web 客户端连接架构决策

## 状态
**已接受** (2026-11-03)

## 背景
Codync 主机 (`codync-host`) 提供两种连接方式：
1. **Loopback HTTP API** (`POST /api/{method}` + `GET /events` SSE) — 仅限本机 loopback + Bearer token
2. **`/channel` WebSocket E2E 加密通道** — 供已配对设备（手机）使用，端到端加密（ChaCha20-Poly1305），X25519 ECDH + Ed25519 签名握手

Web 客户端需要远程连接主机，最初提出 Relay 代理方案（中间服务器持 token 转发），但安全审计（砚边）发现该方案存在 token 持有、CORS `*`、白名单漂移等风险。

## 决策
**浏览器直连主机 `/channel` 端点，端到端加密，无中间层。**

- 删除 `web/bridge/` 中间层方案
- 删除 `web/relay/` 持 token PoC
- Web 客户端实现完整的 `/channel` 协议：X25519 握手、Ed25519 签名、ChaCha20-Poly1305 帧加密
- 权限边界由主机 `permit()` (devices.rs:104-114) 控制，Device caller 可调 103/151 个方法，48 个 LOCAL_ONLY 方法天然不可达

## 理由
1. **安全性**：无中间层持有 token，攻击面为零；主机端 `permit()` 天然拒绝 LOCAL_ONLY 方法
2. **端到端加密**：即使网络被监听，帧内容不可解密
3. **与手机客户端一致**：Web 客户端和手机客户端走同一协议，代码可复用协议理解
4. **无需额外部署**：用户只需运行 codync-host，浏览器直接连接

## 技术要求
- 浏览器端需实现：X25519 (`@noble/curves`)、Ed25519 (`@noble/curves`)、ChaCha20-Poly1305 (`@noble/ciphers`)、HKDF-SHA256
- WebCrypto 不支持 ChaCha20-Poly1305，必须用 pure JS 实现
- 测试向量：`docs/reference/fixtures/remote-relay-vectors.json`（12 组官方向量）
- Close code 映射：4001/4003/4008/4400/4410 → 重连策略

## 工作区约定
**唯一工作树：`/workspace/Codync-2.38.0/`**
- `/tmp/Codync-2.38.0/` 为临时解压目录，产出已同步至 /workspace 树，可废弃
- `/workspace/web/` 为砚台早期孤儿落点，可废弃
- 所有路径统一引用 `Codync-2.38.0/web/...`

## 被拒方案
| 方案 | 拒绝原因 |
|------|---------|
| Relay 代理（Node.js 持 token 转发） | 中间层持有 token，CORS `*`，白名单漂移风险，攻击面大 |
| 白名单 Bridge（仅转发部分 API） | 需维护方法白名单，与主机 `permit()` 双重边界易不一致 |
| WASM 主机浏览器本地运行 | 工作量大（2-3 月），文件系统虚拟化复杂 |
