# 首次连接教程：配对码（草稿）

> ⚠️ **草稿** —— 连接 UI 已实现（`29743ed` + `3f6a918..1ff4bd7`），但与真实主机的
> 端到端联调未完成；配对参数与错误码追溯自主机源码 v2.38.0，交互细节以最终实现为准。
> （榫卯，更新 2026-11-04）

## 准备

1. 电脑上已安装并运行 Codync 主机（装桌面端即可；默认端口 19222）
2. **主机需开启云且已登录**：配对要求云签发的设备证书，无证书的连接会被
   拒绝（close 4400，`certificate.rs` → `channel/pairing.rs:83`）
3. 已有手机等设备连接不影响：同一台主机可授权多台设备

## 连接方式（连接页 `/client`，三个入口）

1. **演示模式**：一键进入，用内置的演示假主机体验界面，不连真实电脑。
2. **配对链接**：在电脑端桌面 App 发起「添加设备」，把配对链接
   （`codync://pair?v=3`）粘贴到连接页，输入框会实时识别。链接自带主机签名
   密钥（`sk`），握手时会强校验 welcome，防中间人。
3. **已配对直连**：之前配对过的浏览器再次使用，直接填主机地址连接。

配对码 **10 分钟有效**，同一主机同时最多 **5 个**（超限等过期或重新生成）。

## 连接失败对照表

握手被拒时主机会下发 WebSocket close code，分两组（源码：
`host/src/remote/channel.rs` 协议级常量、`host/src/api/devices.rs`
RejectCode 映射）。用户会遇到的以 reject 级为主：

| close code | 含义 | 你会看到 | 怎么办 |
|-----------|------|----------|--------|
| 4001 | 未授权 / 租约过期 / 签名错误 | 认证失败 | 重新配对；客户端限 3 次重试后停止 |
| 4003 | 设备已被撤销 | 设备已被移除 | 重新配对（不会自动重连） |
| 4008 | 请求过频 | 稍后再试 | 限流为每分钟 3 次（按来源），等冷却即可 |
| 4400 | 版本不支持**或设备证书缺失** | 连接被拒 | 升级电脑端主机；若主机云未开启/未登录，先在电脑端开启云并登录（配对证书由云签发） |
| 4410 | 配对码已过期 / 已关闭 | 配对码失效 | 回电脑端重新生成一个 |

协议级其余 close code（1000 正常关闭、1011 超时、4002 协议错误、
4011 需重新协商密钥、4013 帧过大、4100 已配对——客户端停止重连）
由客户端内部处理，正常使用不会看到；完整清单见 [API 参考 §5.1](api-reference.md)。

## 已知限制（主机 2.38.0）

- 配对平台白名单只收 `ios | macos | android`（`channel/pairing.rs`），
  Web 端暂以 `macos` 登记配对（连接页有注明）；待主机侧白名单加入 `web`。
- 云登录签发证书的流程 Web 端属 Phase 2；当前连接页留有证书 JSON 粘贴栏，
  可对「云已开启」的主机实测。

## 安全说明

- 配对只兑换**一台受限设备**的身份；之后的全部流量端到端加密
  （ChaCha20-Poly1305），主机只认签名
- 浏览器生成的设备密钥优先用**不可导出**的 WebCrypto 密钥（存 IndexedDB）；
  不支持时回退为加密包裹存储；清除浏览器站点数据 = 丢失设备身份，需重新配对
- 设备可随时在主机端撤销，撤销后该浏览器立即失效（4003）
